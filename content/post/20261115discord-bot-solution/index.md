## 雑談チャンネルが静かなまま、ニュースは誰も共有しない

少人数の Discord サーバーでは、雑談チャンネルが通知の置き場になりがちです。誰かが話しかけても反応が返ってこないので、次の投稿までの間隔が少しずつ伸びていきます。新しく入った人は、会話の途中に入るきっかけがありません。

情報共有にも同じような分断があります。メンバーはそれぞれ RSS リーダーや X で記事を追っていて、面白いものを見つけても、そのまま自分のなかに留めます。「これを共有しよう」と思っても、誰がその話題に興味あるか分からないので、結局貼らない。貼ったとしても、別の人が同じ記事を後日また貼ります。

この2つは別々の問題に見えて、どちらも「共有の入口がない」ことに起因しています。そこで、雑談チャンネルに常駐する Bot **ロブスター** を作りました。会話の相手と、ニュースの共有役を1つのプロセスにまとめた構成です。

## 既存手段の限界

| 手段 | できること | 限界 |
|---|---|---|
| 汎用の挨拶 Bot | 常駐して定型文を返す | 文脈を持たない。会話が続かない |
| RSS リーダー | 記事を集めて読む | 個人のなかに閉じる。共有されない |
| 手動で URL を貼る | 自分の判断で共有できる | 続かない。同じ記事が重複する |
| クラウド LLM の Bot | 自然な会話ができる | 利用料が続く。会話内容が外部に出る |
| 定時ニュース Bot | 決まった時刻に投稿する | 興味と無関係。既出記事も再投稿される |

どれも「会話」か「情報共有」の片方しか担えません。ロブスターが狙ったのは、両方を同じ interests（興味キーワード）でつなぐことでした。

設計の要点は4つです。

- **人格を「友達」に寄せる**: 敬語と AI アシスタント口調を禁止し、1〜3文で返す
- **入口を2つ持つ**: メンション（会話）と定時投稿（情報）を同じプロセスに置く
- **興味を会話で更新する**: 設定ファイルを開かずに interests を育てられる
- **トピック質問で橋を架ける**: 日本語の関心を英語フィードの記事につなぐ

トレードオフもあります。ローカル LLM なので、クラウドの最新モデルに比べると語彙も速度も劣ります。常時起動するマシンも必要です。それでも、会話内容が外部に出ないことと、利用料が固定であることを優先しました。

また、この Bot は自分から会話に割り込むことはしません。反応するのはメンションされたときだけです。「自律的に盛り上げる」のではなく、「呼ばれたら必ず返し、決まった時刻にネタを置く」という設計にしています。

## 実装の要点

### 1. 反応を最速で返す

雑談で一番効くのは、返事の速さです。生成には時間がかかるので、受け付けた時点で 👀 を付け、入力中表示も出します。

```ts
// src/discord/handler.ts
if (!isMentioned) return

// 受け付けたことを最速で知らせる（完了は待たない）
void message.react(ACK_EMOJI).catch(() => {})

const userContent = stripMentions(message.content, botId)
```

`await` しないので、リアクションの往復が生成開始を遅らせません。反応がすぐ返れば、生成待ちも「考えている」ように見えます。

### 2. interests を会話で育てる

興味キーワードは `config/news.json` にありますが、メンバーに JSON を編集させるのは無理があります。そこで、チャットから追加・削除できるようにしました。実行中は `runtime.ts` の配列が真実源です。

```ts
// src/interests/runtime.ts
let current: ReadonlyArray<string> = [...config.news.interests]

export function getInterests(): ReadonlyArray<string> {
  return [...current]
}
```

`config` は `as const` で読み取り専用なので、実行時の値を別に持ちます。追加は Discord の ✅ リアクションで確定し、待ち状態は60秒で失効します。書き戻しは一時ファイル経由なので、途中で落ちても `news.json` は壊れません。再起動は不要で、次の定時投稿から新しい interests が使われます。

### 3. 日本語の興味を英語フィードにつなぐ

「3Dプリンター」と登録しても、英語圏のフィードは `3D printing` と書きます。そのままでは一致しません。そこで、interests と質問文のキーワードを、Ollama で同義語・英訳に展開しています。

```ts
// src/discord/handler.ts（トピック質問の分岐）
const topics = await extractTopics(userContent)
const searchTerms = await expandTerms(topics)
const articles = await fetchAllFeeds()
const matched = rankArticlesByTopics(articles, searchTerms)
```

展開結果は `data/synonyms.json` にキャッシュされるので、同じ語で2回目以降は Ollama を呼びません。定時投稿でも同じ展開を使うため、日本語で登録した興味がそのまま英語記事の選別に効きます。キーワード一致は単語境界を見るので、`CAD` が `academic` に、`Rust` が `Trust` に誤マッチしません。

## 結果

リポジトリに記録されている範囲で、できるようになったことを整理します。

| 項目 | 内容 |
|---|---|
| ニュースソース | 17本（国内・海外、RSS1 / RSS2 / Atom） |
| 定時投稿 | 1日2回、1回最大5件（1ソース最大2件） |
| 重複排除 | 投稿済み 500 URL を保持 |
| トピック質問 | 関連記事を最大3件、関連トピックを最大5件 |
| interests 更新 | チャットから追加・削除、再起動不要 |

定性的には、次の3点が変わります。

- 雑談の入口が「メンションする」の1つに絞られ、返事が必ず返る
- ニュースを貼る人がいなくても、決まった時刻に話題が置かれる
- 興味の設定が会話のなかで完結し、設定ファイルの存在を意識しなくてよい

利用回数や反応率のような効果測定はリポジトリに記録がないため、数値では書きません。ここで言えるのは「共有の入口が用意された」ところまでです。

## 向かないケース・残課題

- **複数チャンネルを回したい場合**: 監視するチャンネルは `DISCORD_CHANNEL_ID` の1つだけです。雑談とニュースを別チャンネルにすることはできますが、雑談を複数チャンネルに広げるには改修が要ります。
- **Bot から話しかけてほしい場合**: 反応はメンション時のみです。定時投稿以外で Bot が自発的に会話へ参加することはありません。
- **会話の文脈を個人ごとに分けたい場合**: 履歴はチャンネル全体で直近20件を共有します。プロフィール要約で補っていますが、同時に複数人が話すと混ざります。
- **マシンスペック**: モデルは Mac mini M4 Pro（24GB 以上推奨）を前提にしています。小さいモデルに替えると速度は上がりますが、口調の安定は落ちます。
- **フィードへの依存**: ニュースのネタは RSS に依存します。ソースが死ぬと記事が減るため、月1回の棚卸しを入れています。
- **音声応答**: 読み上げ機能は実装されていますが、`TTS_ENABLED` がデフォルト無効です。

## まとめ

- 雑談の寂しさは「常駐する人格」と「即時の反応」で扱う。完全自律にせず、呼ばれたら必ず返す形にした
- 情報共有の分断は「定時投稿」と「トピック質問」の2経路で扱う
- 両方を1つの interests でつなぐと、興味の設定が会話のなかで育つ
- ローカル LLM を選ぶと、コストとプライバシーは守れるが、速度と品質は妥協点になる

派手な機能はありません。ただ、誰も設定を触らなくても回り続ける仕組みにしたことで、小さなサーバーでも「置いてあるだけ」の Bot にはならない構成になりました。
