## 図面はある。モデルはない

紙の図面と PDF は残っていて、寸法も材質も書いてあります。しかし CAD データがありません。困るのは形が分からないことではありません。**3D が無いと、干渉の確認も、設計変更の反映も、CAM の工程も進まない**ことです。手でモデリングし直せば形は出来ますが、それは「そう見える形」で、板厚を 1 mm 変えれば穴の位置がずれるようなモデルです。

image2CAD は、この「読み直し」を自動化するプロジェクトです。何を守れば「編集できる3D」と言えるのか、という観点で設計と結果を整理します。

## 既存手段の限界

| 手段 | できること | 限界 |
|---|---|---|
| 手作業でモデリングし直す | 設計意図まで含めて作れる | 時間がかかり、転記ミスも残る |
| 2D CAD にトレースする | 線と寸法がデータとして残る | 3D にならず、押し出しは別作業 |
| 輪郭を押し出して3D化する | 形は短時間で出る | 穴が埋まり、寸法が履歴に残らず数値を変えると壊れる |
| image2CAD | 図面の寸法から PartDesign の履歴を組む | 角柱・円筒・穴の範囲。未対応形状は下記 |

3番目は「見た目は正しいが編集できない」モデルです。欲しいのは寸法を変えても壊れない履歴でした。

設計の要点は3つです。

- **寸法を正とする**: 図面の寸法値から座標を組み立て、式として持つ。実測値しか無い箇所は保証の外だと明示する
- **履歴を機械的に検査する**: Body が1つ、ブーリアンなし、全スケッチ完全拘束、`Params` シートあり、各パラメーターを 5% 変えても壊れず形が動くこと
- **検証を3段にする**: 再投影比較、DXF の往復、入力図面への描き戻しを、別の視点で3回確かめる

自動修正はしません。crosscheck がエラーを出したら止め、食い違いをレポートで返します。誤って直すより、人が判断する段だからです。

## 実装の要点

### 1. 寸法を式にする

座標は寸法のつながりをたどって1次式にします。`src/image2cad/infer/params.py` の `Lin` が式で、`render()` が IR に書ける文字列にします。

```python
# src/image2cad/infer/params.py（Lin.render）
for k, c in sorted(self.terms.items()):
    if abs(c - 1) < 1e-12:
        s = k
    elif abs(c - 0.5) < 1e-12:
        s = f"{k}/2"
    else:
        s = f"{round(c, 6)}*{k}"
    parts.append(s)
expr = " + ".join(parts).replace("+ -", "- ")
```

この式が IR に入り、FreeCAD の `Params.L/2` に変換されます。`Params` のセルを変えれば、穴の位置も外形も追従します。寸法で決まらない値は `measured` として記録し、`fully_dimensioned` を false にします。±0.01 mm の保証は寸法に裏打ちされた値だけです。

### 2. 「編集できる」を検査にする

`src/image2cad/validate/freecad_validate.py` は各パラメーターを 5% 変えて再計算し、モデルが壊れないこと、頂点座標が実際に変わることを確かめます。どこにも結びついていない飾りのパラメーターは、ここで落ちます。

編集可能性を合否で扱うための仕掛けです。拘束が足りないスケッチや式が届いていない数値は、動かして初めて分かります。

### 3. 失敗をレポートで返す

読めなかった図面は例外ではなく、段の名前つきで返します。

```python
# src/image2cad/pipeline.py（drawing_to_model）
if not cc["ok"]:
    report["ok"] = False
    report["stage"] = "crosscheck"
    _dump(out / "report.json", report)
    return report
```

`stage` は `crosscheck` / `infer` / `build` / `validate` / `verify` / `roundtrip` のどれかで、どこで落ちたかが分かれば原因を切り分けられます。GUI（`uv run python -m image2cad.gui`、127.0.0.1:8765）でも、検証を通ったモデルだけがダウンロードできます。

## 結果

リポジトリに記録されている数値です。

| 対象 | 結果 |
|---|---|
| TechDraw の図面 20 枚（独立ソース） | パイプライン 20/20、validate 20/20、寸法 170/170 |
| 描画スタイルを変えた 200 枚 | 寸法 1700/1700 |
| 往復検証（10 部品 × 2 スタイル） | 寸法・角度が全件一致 |
| 合成スキャン L1（300 dpi） | 10/10 部品がモデルまで合格 |

TechDraw の 20 枚は対応前が 0/20（例外落ち）で、修正のうえで 20/20 になりました。

効いているかも確認しています。パラメーターを 0.02 mm ずらしたモデルは往復検証で全件不合格になり、複雑形状 16 ケースでも**誤合格は 0 件**でした（形状一致 11、往復検証で拒否 2、時間切れ 2、ビュー欠落 1）。

作業は、図面を見ながらの転記から「読み取り結果と検証レポートを見て採否を決める」に変わります。完全自動ではありません。

## 向かないケース・残課題

- **フィレット・面取り・回転体・断面・止まり穴・底面側の凹み**: 未対応です。推定できない形は `Unsupported` として別方向の候補に回します
- **C・t・SR・Sφ・M・角度の注記**: 読み取りますがモデルには反映せず、`unused_notation` の警告にします
- **パラメーター名**: `x_pos_1` のように機械的です。設計意図に沿う命名（穴ピッチ、溝幅）は未対応で、対称配置の穴をピッチ1つで表す表現もありません
- **外部ソースの検証範囲**: TechDraw の A3 テンプレート1種のみ確認済みです。矢じりが三角形以外（開いた矢、点、斜線）は未対応です
- **写真**: 透視歪みの補正は未対応です。スキャンも複数 seed では合計 150/160 で、全数ではありません
- **類似図面の検索（M6）**: 未着手です

「角柱・円筒・穴で、3ビューが揃った図面」なら強く、外れるほど人の確認が増えます。

## まとめ

- 「編集できる3D」の条件を「寸法が式で入っていること」と定義し、検査に落とす
- 生成できたかではなく、図面と合っているかを3つの視点で確かめる
- 直せない食い違いは自動修正せず、段の名前つきで返す

大事なのは、読み取れる範囲を正直に区切り、その範囲では検証で保証する形だと考えています。
